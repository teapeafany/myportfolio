Research and testing

The concept was simple: lasers would act as invisible strings, beaming down on photoresistors, which would read light levels.

When the player blocks a beam, the value drops, and that change has to reach the music software on my computer somehow. I read a lot of threads and build logs to sanity-check the idea.

Print handoff

Final STL out the door—first print run clocked in around eight hours.

I got started on CAD early because printing would take a while. Plenty of Venti’s-lyre meshes exist online, but after struggling to edit one as a mesh body, I built my own so I could hide an Arduino, route wiring, and place holes exactly where I needed them. I had never used Fusion before—nothing like the simple table from my last project—so reference images, splines, and extrudes came together with a crash course from a friend (thanks Tanmay!). We iterated measurements and sent STLs to another friend with a printer; outside the HIVE queue, that extra printer access mattered a lot.

Our first CAD model included a base: about 14 inches tall and 1.5 inches thick. Then came the first hard constraint—the machine I could use couldn’t handle that size, and the part had to get much thinner. Fitting the protoboard and Arduino fully inside turned out to be a pipe dream, so I kept them moderately external, which stayed workable.

After those adjustments, the numbers I landed on looked like this:

  • Top holes (6 mm lasers, with tolerance): 6.3 mm
  • Bottom laser holes (so beams don’t fall through): 4.7 mm
  • Overall height: 10 inches
  • Bottom photoresistor holes: about 5 mm

The bottom of the lyre stayed hollow for photoresistor wiring. When the model was finally done, I sent it off to print—the run took a whopping eight hours.

Focus

Fusion geometry pushed by real printer limits: thinner walls, external electronics, tolerance-aware holes, a hollow base for wiring, then an STL validated through friend-and-queue print passes.

Arduino — stream readings (excerpt)

const int PIN_COUNT = 6;
const int PINS[PIN_COUNT] = { A0, A1, A2, A3, A4, A5 };

void setup() {
  Serial.begin(115200);
}

void loop() {
  for (int i = 0; i < PIN_COUNT; i++) {
    Serial.print(analogRead(PINS[i]));
    if (i < PIN_COUNT - 1) Serial.print(',');
  }
  Serial.println();
  delay(5);
}

Firmware → USB

The Arduino samples every photoresistor and prints one CSV line per frame so the laptop always sees a stable, ordered snapshot of all strings.

Python — serial to MIDI (excerpt)

import serial
import mido

SERIAL_PORT = "/dev/cu.usbmodem101"  # your port
BAUD = 115200
THRESHOLD = 380
NOTES = [60, 62, 64, 65, 67, 69]
was_on = [False] * len(NOTES)

ser = serial.Serial(SERIAL_PORT, BAUD, timeout=0.02)
out = mido.open_output("Your Virtual MIDI Port")

try:
    while True:
        line = ser.readline().decode(errors="ignore").strip()
        if not line:
            continue
        vals = [int(x) for x in line.split(",")]
        for i, v in enumerate(vals):
            if i >= len(NOTES):
                break
            on = v < THRESHOLD  # beam blocked → dimmer reading
            if on and not was_on[i]:
                out.send(mido.Message("note_on", note=NOTES[i], velocity=100))
            elif not on and was_on[i]:
                out.send(mido.Message("note_off", note=NOTES[i], velocity=0))
            was_on[i] = on
except KeyboardInterrupt:
    ser.close()

Host → MIDI

Python reads serial, applies a light threshold so a blocked beam reads as a hit, and emits note-on/note-off on a virtual MIDI port for a DAW or soft synth.

Once the hardware was reading light levels reliably, the instrument still wasn’t “musical” until the laptop understood those readings as notes. I kept the firmware dumb on purpose: the Arduino only streams analog values over serial as comma-separated numbers—one row per scan—so I could tune thresholds and voicing in software without reflashing every time I changed my mind.

On the host side, a Python script opens the USB serial port, parses each line into per-string brightness, and compares against a cutoff (when a laser is blocked the photoresistor dips). Crossing that boundary triggers MIDI note-on; clearing it sends note-off. Output goes to a virtual MIDI bus (e.g. IAC on macOS or loopback on Windows) so any DAW or standalone synth can receive the lyre like a normal controller. Velocity is simplified for now; the important part was getting predictable note fires while I played.

Focus

Thin firmware that only ships sensor truth over serial; a Python MIDI bridge for thresholds, debouncing feel, and DAW-ready note traffic without constant hardware flashes.

Plan & fit-up

Next was wiring the rest of the lyre strings and soldering to the protoboard—it needed planning, but I’d soldered before and wanted to stay efficient on the bench.

When the 3D print arrived, I dry-fit everything first. Once the fit felt right, I moved into real solder joints.

Prep & through-hole

I cut wire to length and stripped ends up front so the harness stayed organized instead of turning into a bird’s nest.

Then I soldered photoresistors, resistors, and analog pins, plus ground and 5 V.

Lesson learned

Don’t solder photoresistor legs before you thread them through the lyre holes. I forgot—and had to add extra jumper wire to reach the board. Not a disaster, just more time.

Lock & finish

Four strings stable—glue for beam alignment and for parts knocked loose while handling.

Laser wiring

The lasers fought me more than they should have. I tried to run everything off two buses—one positive, one negative—and soldered and desoldered more than once.

After cutting and redoing runs, the leads were too short. In the final build the bundle sticks out more than I wanted; I’d hoped to tape leads neatly along the sides of the lyre.

Lock-in & glue

When all four strings behaved, it finally felt like the endgame.

I hot-glued the lasers so they wouldn’t wander off the photoresistors, and dabbed glue anywhere a part had popped off when I handled the board too hard—something I wish I’d used more on the cat project.

Focus

Repeatable bench discipline (prep, fit, then solder), honest rework on shared laser power, and mechanical locking—glue—so optics stay aligned under handling.
